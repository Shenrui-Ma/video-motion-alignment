历史 physical 评估异常隔离审查

最终结论
R71 P1 是本次审查唯一确认受到连带 UNKNOWN 影响的实际结果。已用原缓存重算 R55 五组、R50retry chest 一组、R65 两组、R66 八组，共 16 组历史配对：逐视频的可测性和合格时差结论均未变化；480 项原来可测的诊断与归档数值完全相同，最大绝对差 0。
官方 MF 结果和在线 source→单个 current-x0 观察器均不受本问题影响。

影响原理与代码范围
1. IVEBench evaluate90.evaluate：在同一个 try 内提取 reference、native、auto 特征；任一目标缺少躯干锚点，会将两条目标该 confidence 下的整组固定窗口标为 unknown_visibility。源文件位于 R26/analysis/ivebench_physical_time_eval_20261017/evaluate90.py，SHA e03ea8dd6504ab54b56d20b4f6cdc0991f1bd80de8d112870a2754469a42129e。实际使用者为 R55 五组最终 physical 配对及 R71 本次原版 physical 配对。
2. FlexiAct evaluate.evaluate 具有同样结构。源文件位于 R26/analysis/flexiact_physical_time_eval_20261017/evaluate.py；R65/runtime/physical/evaluate.py、R67/runtime/physical/evaluate.py 为相同字节副本，SHA 6d41b7c258496d7bf7bee259601046ed3e788e7b1d3ac9267695ab0022159cc0。实际配对调用为 R50/R50retry、R65 与复用 R65 evaluator 的 R66。
3. IVEBench shared_support.py 也包含这个 FlexiAct 函数副本，但 evaluate90 仅导入其中的 common_error，并没有调用其 evaluate。R67 实际的 roundtrip/current-x0 诊断只调用 original_time_view/diagnostic；每个输出独立处理，未进入有问题的双目标 evaluate。
完整源代码位置、文件 SHA、AST try 范围见 TRY_INVENTORY.json。两种存在风险的 evaluate 在 7 个代码副本中出现；需要区分包含函数的副本与实际调用路径。

不受影响的流程
在线 scan_current_pose.observe 每次只有 reference 与一个 current-x0 target，不存在另一个生成变体使它失败的通道。source 与 current-x0 任何一者确实不可测时继续 UNKNOWN，符合既有规则。
R27–R53 的 fixed_metrics 原本在目标循环内独立 try；common_regions 的全方法交集要求全部输入可用，仅影响共同可见区域比较，不会抹掉那些独立诊断。
官方 MF 路径读取 CoTracker 轨迹，调用 score_cached_tracks.score 或 metric_adapter.score_tracks；不读取 DWPose physical 的 UNKNOWN。已核 R63、R65、R66 的 scripts/score_one.py，故历史 MF 数值无需重算。
