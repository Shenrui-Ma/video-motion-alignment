# 新 1024×576 native 的独立结果审查

正式 run：`s05_seed1_native`；ComfyUI prompt ID `db887de8-4476-4ff3-9ead-266ff76afd19`。由 `/history` 的 success/completed 状态和 SaveVideo 实际输出确认，文件 `s05_seed1_native_00001_.mp4`，1024×576、141帧、24fps。

## 结论

**此新基线未复现旧 Sam05 的明显局部延后，不能用它证明干预“修复了+13帧错位”。**

| 源帧窗口 | 双臂方向最佳 lag（0.3阈值） | 同帧方向误差 | 0.5阈值复核 |
|---|---:|---:|---|
| 50–65 | −1帧 | 0.123 | −1帧，稳定 |
| 69–81 | −1帧 | 0.495 | 关节覆盖不足，不作可靠lag解释 |
| 80–92 | 0帧 | 0.092 | 0帧，稳定 |
| 99–111 | −1帧 | 0.080 | −1帧，稳定 |

帧0为起点，正lag表示编辑动作延后。−1帧在此应解释为接近同相位，而非重大“抢拍”。未加权旧1312样例首窗同帧误差1.126、lag+13；当前并不是那条旧基线的严格数值复现，分辨率与本轮运行环境不同。

右腕过肩事件源帧依次49、66、76、106，当前native为49、66、74、105。第55帧已人工核验：源与新native均有对应的右手抬起和右腿弯起，Sam外观替换存在，骨架定位可靠。它不是姿态检测器把实际的明显延后漏掉。

141帧零人物漏检、零多人/选人歧义，主要COCO身体关节置信度覆盖超过99%。所有低置信结果仍保留在JSON，没有只报告有利窗口。

## 实验含义

当前样例仍能用于测试干预是否破坏正确动作，以及错误时间路由的反事实影响，但不存在足够的待修复时间误差来证明纠错能力。建议下一步先复现原1312设置或使用事先规定的其他种子，确认明确失效基线，再启用多方法比较。不要通过修改测量窗口或降低置信门槛让当前native“看起来失败”。

本审查不执行GPU调度，不改变主实验方案。等待主任务指定下一正式run。
