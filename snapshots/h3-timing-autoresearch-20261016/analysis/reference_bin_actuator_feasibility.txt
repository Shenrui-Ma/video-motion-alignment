Bottom-line facts

time_offset is a signed INTEGER REFERENCE LATENT-BIN displacement. For output
query bin j, radius0 selects all spatial K/V tokens in reference bin
clamp(j+time_offset,0,T-1). Positive means later reference bins, negative earlier.
It does not shift output frames, change the sampler timestep, or directly change
RoPE coordinates. It uses already native-RoPE Q/K and the actual selected V.

An offset of one bin is NOT a constant four physical frames. The positional-bin
spans repeat 1,4,4,4,4. In the present window, +/-1 corresponds to a signed 1 or4
frame start-coordinate displacement; +/-3 corresponds to signed 9 or12 frames.
These are positional bins, not disjoint VAE receptive fields or guaranteed visual
event displacements. Positive offset would advance motion in an ideal direct
copy system, but the learned network's actual signed response remains untested.

Critically, time_offset=0 is STILL an intervention in mass_preserve mode with
alpha>0. It routes reference mass to the same bin. Only alpha0 or mode=native
switches that actuator off. This differs from PhaseRoPE, whose delta0 is native.

Bounds and truncation

Define c=clamp(j+d,0,T-1), A_j=[max(0,c-r),min(T,c+r+1)). Supported r=0 or1.
The implementation clamps the CENTER first, then clips the neighborhood.
Example: T42,j0,d-3,r1 selects bins[0,2), not an empty set and not three copies
of bin0. j41,d+3,r1 selects[40,42). Every selected bin appears once per query.
Different query bins may collapse onto the same edge bin after clamping. This
does not duplicate K/V within an attention row, but can flatten temporal variety.
There is no cross-query conservation/one-to-one assignment constraint.

Radius0 always has943 keys per query-bin group in this geometry. Radius1 has
2 or3 actual bins at boundaries/interior. Neighborhoods are batched according to
their true lengths, without padded/duplicated edge keys. All943 spatial positions
participate; this is temporal localization, not a hand/arm spatial mask.

Same-input mass conservation: exact algebra versus implementation precision

For a fixed layer/forward and fixed native Q,K,V, let R be ALL video-reference
keys, A_j its shifted selected-bin subset, l_k=q dot k/sqrt(D), and
  Z=sum_all exp(l_k), Z_R=sum_R exp(l_k), Z_A=sum_A exp(l_k),
  p_k=exp(l_k)/Z, m_R=Z_R/Z,
  O=sum_all p_k v_k,
  O_R=sum_R exp(l_k)/Z_R *v_k,
  O_A=sum_A exp(l_k)/Z_A *v_k.

Frozen mass_preserve implements O'=O+alpha*m_R*(O_A-O_R).
Equivalently, for alpha in[0,1]:
  p'_k = p_k                                      when k outside R;
  p'_k = (1-alpha)*p_k                             when k in R but outside A;
  p'_k = (1-alpha)*p_k+alpha*m_R*exp(l_k)/Z_A        when k in A.
Thus sum_R p'_k=m_R and all non-reference probabilities/contributions are
unchanged in exact arithmetic, for any valid signed offset. At alpha1 the entire
original reference-group probability is redistributed inside A; it is not extra
reference-group strengthening. Within A, native content/position scores remain
unequal: this is not uniform copying of all selected reference pixels.

The code uses Flash LSE_ref - LSE_all in FP32, clamps tiny positive log-mass to0,
and casts corrected output back to BF16/FP16. Original/ref/aligned attention
outputs already contain rounding. Therefore the real implementation approximates
the exact redistribution; it does NOT promise bitwise conservation of an explicit
probability matrix (none is materialized). Nonselected query outputs are copied
from the native Flash output unchanged at this call. Following residuals/layers
and denoising steps change states, so reference mass is NOT held equal across
complete native/intervened runs. No claim is made that appearance is unchanged.

hard_route is different: it removes R\A logits and globally renormalizes among
A plus all non-reference keys. Its resulting reference mass Z_A/(Z_other+Z_A)
is generally <=native m_R. It does not preserve non-reference probability mass.
Root's report that hard and mass results are essentially equal means current
evidence does not establish mass preservation as necessary. It is consistent
with temporal restriction being the active ingredient, but not a unique proof.

Audit interpretation caveats

validated_layout.key_interval_half_open and key_first_time_coordinate describe
the NOMINAL same-bin window reconstructed by validate_layout. They are not
recomputed for time_offset. Reconstruct the actual shifted key sets from audit
time_offset/radius plus latent_interval and frame_rows; do not label the nominal
key interval as the actual nonzero-offset selection.

temporal_readouts are explicitly PRE-intervention native QK distributions inside
the full reference group. They are not post-routing probabilities or motion
ground truth. Different runs can produce different pre-intervention readouts
through upstream state changes, but that alone does not measure action timing.

Reference K/V here are current transformer hidden tokens after native RoPE and
preceding layers, not clean isolated raw-frame motion vectors. They may already
contain temporal/spatial/identity/background mixtures. The actuator cannot promise
to change only pose timing or exclude appearance copying.

Comparison with the existing PhaseRoPE actuator

Same-bin native outputQ-refK time-coordinate gap is235 units for source05.
Let S(j)=sum_{k<j}(1,4,4,4,4)[k%5]. Routing Q_j to reference bin j+d changes the
pair's existing coordinate gap to 235-(5/3)*(S(j+d)-S(j)), while also changing
actual key AND value content. PhaseRoPE leaves all reference keys/values eligible
and instead rotates the temporal pairs of the output-Q reference branch by
delta_frames*(5/3), giving same-bin gap235+delta_frames*(5/3).

Accordingly a +3 bin route produces native selected-pair gaps215 or220 units;
a -3 route produces250 or255. Phase delta-12 gives215 for the SAME original key,
whereas delta+12 gives255. Matching a scalar gap does not make the methods equal:
bin routing changes support and K/V content, phase rotates Q and soft-redistributes
over the entire reference video. Neither resets the native origin offset.
This apparent opposite coordinate sign must not be treated as a proven opposite
motion-control sign. RoPE is periodic/content-dependent and learned generation
is not a nearest-time-coordinate lookup.

Both mass-preserving variants conserve the original reference-group mass at the
same input state algebraically, but their zero points differ:
  router: time_offset0,alpha1 = same-bin restriction (already strong guidance);
  phase: delta0 = exact native fast path.
A phase +/- curve centered at native cannot be compared directly to an offset
+/- curve centered at same-bin mass routing without explicitly showing both
native and offset0 controls.

Contingency decision, not a new run recommendation

The current static offset API can express the contemplated signs without any new
model architecture or code. A fair later signed response diagnostic would compare
native, offset0 mass, and predeclared signed offsets using identical source/seed,
geometry/prompt/backend/window/layers/steps/alpha. First establish whether the
late intervention gate is effective; a sign-controllable all-steps oracle does
not establish controllability after a reliable step10 observation.

The minimum useful empirical question is whether offset-induced changes in signed
lag are reproducible and order-consistent while preserving edit quality, later
events and the successful native cases. If both signs improve equally, selection /
regularization rather than directional correction is plausible. If signs do not
move lag predictably, it cannot serve as a calibrated feedback actuator merely
because one seed improves. Do not choose a best offset post hoc and call it an
automatic controller. Current fixed manual window is still an oracle assumption.

An offset parameter, temporal mask, or normalized reference redistribution alone
does not resolve novelty overlap with existing frame-aligned/routing methods.
No new literature claim is made here. The purpose is to audit a bounded fallback
implementation and its falsifiable semantics while current late/phase outcomes
are pending, not to proclaim an architectural contribution.
