下一候选的进入／停止门槛：参考时间覆盖的最小容量投影
日期：2026-10-16。独立方法审查；只新增本文，不修改代码、GPU、配置或其他报告。

结论先行

目前不建议立即实现或排队新的“架构创新”。唯一值得条件保留的候选是：在冻结 H3 当前层、单头的实际 output-query→reference-video 权重上，保持每个 query 原参考总量，用区间式列容量约束做最小 KL 投影。它不是已确认的创新，也未获得当前实验支持。它应排在同配置 native 复验与机制可观测性检查之后。

特别重要：本轮研究问题主要是动作延后／局部时间错位，而不是稳定漏掉动作。时间覆盖不足和时间错位不是同一个量；即使覆盖完全均衡，也可把所有动作放错时间。因此覆盖候选也可能根本不适合当前问题。若下面 Gate 1 不通过，应放弃此候选，不为获得新模块而增加动态阈值、训练探针、复杂 OT 或静动支路。

一、新证据如何改变判断

父任务新结果：1024×576 的正式同 seed native 视频基本对齐（约 −1 帧）；旧 1312 输出在预指定片段约 +13 帧。应记录为“当前条件下错误未复现”，不能宣布降低分辨率修复了时间错位。跨分辨率相同 seed 不产生相同维度的逐元素噪声；预处理、参考／目标几何、后端和运行版本也要逐项核对。回到当前流程的 1312 native 复验，才判断老问题是否可重现。当前低分辨率 mass 只适合作正常样例破坏性检查，不能把不存在的 +13 帧当其改进空间。

父任务提供的正式 readout：正常 1024 native，在 block 25、8 heads×8 个中心空间位置采样，query bins 14–19 的参考条件均值偏移，在 steps 0/5/10/15/19 分别约 +6.79/+7.067/+6.905/+6.109/+4.749 bins；同 bin mass 约 .014–.021，±1 bin 约 .048–.066，最终视频却基本正确。
这已反证“该 head-average、中心点平均参考时间偏移大，就说明动作 lag 大”的简单判据。不能再拿它作触发器或把对角 attention 当成功指标。它尚未反证所有内部时间诊断：中心点未必位于动作 ROI，头功能不同，跨帧读外观本来可能合理。

现有 readout 也不是候选所需的 coverage：条件 p_ref 的 head／spatial 平均，不等于按各 query 原 refmass m_q 加权的列总量 Σ_q P_qj。不能从前者直接推出后者。若缺少动作 ROI、单头信息和 m_q，应该明确说数据不足，而不是补一个阈值。

二、为什么只保留这个候选，不保留其他包装

不采用全局均值 V residual：在 refmass 守恒下与 full-V 路由严格相同。
不把静态同帧 mask 作为新方法：Vidu S2 与 Wan-Animate-2 已有直接先例。
不以“现在加入 Sinkhorn”作为贡献：Sinkformers／ESPFormer 已有双随机 attention，Slot-ID 已有 reference-video capacity-balanced reader，FreeMix 已有视频编辑 OT。详见 innovation_assessment.txt。

这里仅保留一个可验证差别：每行独立 soft-time/mask 无法主动协调不同 query 对参考时间的累计占用；容量投影通过共享列乘子耦合它们，而且只在容量约束违反时做最小必要改动。该差别在数学上真实存在，但“真实不同”远不等于“有意义且新”。若提升完全由一个固定全局参考帧偏置解释，仍没有足够的机制贡献。

三、最小可实现定义（先不加动态调度、不加时间对角成本）

作用域：一个明确的 DiT layer/head 与已指定去噪步骤，单独处理参考视频组 R，不混入参考肖像、文本、音频或生成视频 keys。第一轮只在既定步骤与层做机制试验，不同时搜索几十个配置。

Q：覆盖整个片段的一组输出主体 query。最小诊断可用源视频手工圈定的主体／动作区域，经已验证的空间几何变换映射到输出 patch；它是 oracle ROI，须明确标注，不能声称自动动作定位。初次干预不要使用仅中心 8 点的粗探针来决定整个主体的权重。若选全画面 Q，须分开报告主体与背景列覆盖，防止背景填满预算而动作仍错。

参考时间分组 j=1..J：按已验证的实际采样时间与 VAE 时间感受野构建，不能直接假设第 j 个 latent 等于第 j 个视频帧。第一轮可以使用模型的 J 个有效参考 latent bins，明确其物理映射和首帧特殊性。

对当前原始 attention A，定义：
  P_qj = Σ(k∈参考时间组j) A_qk，m_q = Σ_j P_qj。
P 是实际未干预权重，不是只取某一组 QK 后另做 softmax 的条件分布；若手里只有条件分布 p，必须乘回真实 m_q。

定义物理时间占用基准：
  H_qj≥0，Σ_j H_qj=1。
H 表示 query q 的物理感受时间对各参考时间组的重叠分配，仅用于生成覆盖预算，不作为每行强制 mask。若感受野不同，按时间区间重叠归一化；无重叠的 query 不应凭空硬匹配，先退出作用域。
  c_geo,j = Σ_q m_q H_qj。
它的总量等于 Σ_q m_q，也随当前已存在的 refmass 分布变化。该构造避免把“每个 latent token 等量”误称“每个物理时刻等量”，但仍是研究假设，不是自然定律。

区间预算而非精确均匀边缘：
  L_j = (1−η)c_geo,j，U_j = (1+η)c_geo,j，0<η<1。
最小探索可预先固定 η=.5，明确这是一个任意但透明的探索设置，不是理论阈值；不能看到结果后不断选 η。c_geo,j=0 的组若本来有合理参考作用，不能直接给 U=0 强制删掉；应只对可定义且有正占用的组设约束，其他组保持无上界／零下界，由总 rowmass 耦合。若因此预算无法辨别真正异常，也应接受候选无效。

求解严格凸的最小改动问题：
  min_X Σ_qj [X_qj log(X_qj/P_qj)−X_qj+P_qj]
  subject to X_qj≥0，Σ_j X_qj=m_q，L_j≤Σ_q X_qj≤U_j。
不加 |τ_q−τ_j| 成本，不加同帧硬 mask，不加严格单调要求。这样第一轮测试的确是跨 query 覆盖约束，而不是把已知同帧机制藏进 OT 成本。

在正支持、可行条件下解唯一。如果 P 已满足约束，则 X=P，干预严格恒等。若 P 不满足，解可写成：
  X_qj = m_q · P_qj exp(θ_j) / Σ_r P_qr exp(θ_r)。
θ 是跨 query 共同求出的列乘子：下界激活时增加该列，上界激活时压低该列，非激活列对应乘子为零（考虑行归一化的共同常数不识别性）。通过小规模凸对偶／带不等式投影的迭代缩放求解，而不是随手对每列裁剪后结束。

实际 lifting：对 k∈参考时间组j，令 A'_qk = X_qj·A_qk/P_qj；非 R 权重逐项保持原值，非 Q query 逐项保持原值。该层当前计算内精确保每 query refmass、各参考组内空间条件分布，满足列区间；不承诺后续层、后续去噪步继续守恒。
若 P=0 或 m=0：m=0 的行保持零；结构性 mask 的零支持不可被 epsilon 悄悄绕开，先检验可行性；数值下溢用 log-domain 求解。不可行就不干预并记录原因，不能改成 unbalanced OT 后还声称精确约束。

实现成本：J 当前约 42，但 Q 可很大。Q×J 本身小于 Q×全部参考 token；计算它仍需要跨所有参考 spatial keys 的精确按组 logsumexp／mass，不是“免费”。可分 query chunk 两遍计算：先统计 P 和 m、求列乘子，再用现有参考支路／logits 修正生成 actual output。必须测额外 kernel、内存、耗时。只对 coarse proxy 运行投影，再逐 query 归一化，不会自动保最终列预算。

四、这个定义如何与同帧 mask 区分，也如何仍可能撞 Slot-ID

同帧 mask 是每个 query 的局部独立规则；本候选共享 θ_j，会因另一个 query 的需求变化而改变本 query 的分配。构造试验：
  P=[[.9,.1],[.8,.2]]，两列上下界为 [.5,1.5]。
投影约为 [[.824235,.175765],[.675765,.324235]]，列和 [1.5,.5]。
只将第二行改成 [.3,.7]，P 的列和成为 [1.2,.8]，已经可行；因此第一行原样 [.9,.1]。第一行原 QK 没变，却因另一行变化而得到不同干预；这证明它是 query 间容量耦合，不是静态单行 mask。

但 Slot-ID 同样具有跨 slot 的容量耦合。我们的区别仅在作用对象与约束含义：生成器现成 query 的实际原 refmass 必须保留、列指向物理参考时间而非 identity token、区间可行时严格不变、无需训练 identity-reader/LoRA。把这些条件列出来可以明确不同实现，仍不足以称架构创新。必须证明本任务需要这些条件，而且把 Slot-ID/Sinkformers 式均匀等式平衡直接搬进来不能取得同样的收益／编辑保真。

最危险反例：
  P=[[.05,.95],[.95,.05]]，两个输出时刻各读错另一个参考时刻。
列和恰好 [1,1]，任何围绕 [1,1] 的上述容量区间都满意，投影恒等；时间对应却几乎全错。循环移位或局部来回换帧也可以保持列总量。这直接说明“覆盖正确”既不充分保证“动作时间正确”，也未必能诊断当前的延后。不能看到这种失败后立即加对角成本，再把成功归给覆盖。

五、必须按顺序通过的 gates

Gate 0：错误复现与测量可信
- 当前 1312×736 native 复验。固定已审计条件、噪声形状、backend、步数、FPS、原始帧对应；明确它与旧 pipeline 是否相同。
- 原始视频上的预定动作 onset/peak/offset 与局部 pose 曲线共同核对，带置信度；不能只用自动 lag 一个数。
- 若当前全分辨率也基本正确，记录未复现并停止针对该单例设计新模块；下一步应是固定小集测发生率，而不是挑更坏 seed 建新故事。
- 1024 当前作为正常样例：如 aggressive mass 破坏动作或编辑外观，先报告它是破坏性干预；不要把失败归因于“需要更复杂架构”而跳过证据。

Gate 1：覆盖假设是否与故障有关系（候选进入门槛）
收集当前配对 good/bad native 在预定的动作 ROI、单头／少量固定层上的真实 P、m 与列占用；背景 ROI 作排除对照。一个机制 pilot 可以先用一个可复现坏例＋一个正常例，但没有另一个 seed／片段就不主张分类泛化。
检验：出错事件对应的参考时间容量是否确实缺失、过度占用是否落在替代动作段，且区别不是因为主体区域大小／m_q 总量变化。必须看错误输出动作的时间区间与参考事件的具体对应，不要求简单 attention 均值等于 lag。
最小可接受证据：预先固定的 probe 规则在坏例产生清楚违反预算，正常例大体可行或明显较少违反；另一个独立 seed／片段验证相同方向。阈值或层／头如果是在发现集选的，必须冻结后在保留集检验；不能只挑能够分开两条视频的头。
停止条件：正常视频同样强烈违反；坏视频覆盖本来正常；只有将 ROI／head 按结果精调后才可分；或者原有中心平均时间偏移仍是唯一支持信号。发生任一项，不启动容量干预的 GPU 试验。

Gate 2：算子资格，先 CPU 小矩阵再 GPU
- 满足预算的矩阵必须严格 identity；包括时间完全错误但覆盖满足的反例，不能偷偷加入时序修正。
- 对每个 actual query 验证 refmass；非参考组与非 Q 完全不变；actual 列上下界误差达预定容差。
- 上述“两行耦合”反例成立；coarse-lifting 反例被避免；支持不满足时透明退出。
这些只是实现正确性，不证明视频有效，更不证明新颖。

Gate 3：最小干预试验（只在 0–2 通过后）
坏例与正常例各一条 native，配对同 seed。先固定一个层区间、一个采样区间、一个 η，不做大网格搜索。
必须区分五类操作：native；普通已有 same-time/soft-time 适配基线；本候选纯容量投影；同一模型内均匀等式平衡；将坏例算得 θ 固定复用于其他例的参考时间偏置。
第一轮允许先跑 native/纯容量两个版本排除显著无效，若无收益立即停；只有正结果才补其他基线。成功定义是预定事件时间误差下降且编辑形象不回退，正常例不劣化；不存在只看 attention 更均衡就成功。
均匀等式对照用于判断是否只需要通用 Sinkhorn；冻结 θ 对照判断是否复杂的 per-input capacity 求解只是一个可替代的固定 gain。比较时报告干预 KL、校正输出范数／熵，避免更大干预占便宜。

Gate 4：能否继续谈创新
至少须同时存在：可复现的任务故障；与 coverage 有关联且不是既有 attention sink 的泛化重述；纯容量投影相对单行时序路由有独立收益；保持原 refmass 和区间 no-op 条件确实改善编辑／时间取舍；固定 bias 与通用均匀平衡不能解释；第二 seed 与第二未选片段仍成立。
即便以上成立，也只能说“有一个值得扩大验证的机制”，还要扩数据与更广 prior search。若只有单 H3 单失败样例改善，应定位为实验发现／工程修正，不能据此宣称顶会架构创新。

六、对当前排队计划的建议

保持当前计划：1024 mass 作正常样例检查；1312 当前 native 先复现；之后才解释 intervention。不要为了本文再追加容量实验或自动控制器。特别不要用已被正常样例否定的中心/head-average 参考时间偏移控制何时引导。

当前候选状态：CONDITIONAL HOLD / NOT READY TO IMPLEMENT。
最可能使它被否定的原因：已有问题只是时间相位重排，没有参考时间覆盖缺失；或自然跨帧外观读取使 coverage 先验在好坏视频上都大量触发。若如此，诚实的下一步是冻结这条方法方向，建立可复现故障与对照集，而非在 OT 上再加一个模块来满足“必须创新”的目标。
