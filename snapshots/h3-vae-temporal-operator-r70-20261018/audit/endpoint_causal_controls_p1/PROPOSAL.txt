1. 现有证据支持检验什么

R67 的原参考 VAE encode→decode 在 fitness 前两秒、两档姿态置信阈值下，双臂及左右臂时差均为 0，覆盖率均为 100%。这条参考输入的 codec 重建保留了被测动作时间。
R67 的 Native 中间预测在 index5 已显示双臂 375 ms、左臂 250 ms、右臂 375 ms 的偏移；index6 固定 attention 引导后，合并测量降至 250 ms，但两臂各自测量未改变，最终仍为 375 ms。这支持检查早期预测和执行器的响应，尚不足以把原因定位为某一层注意力。
R70 从 Native index6 自身预测拟合时间映射，前两秒双臂方向误差 .400769→.208729，未参与拟合的前臂 .439771→.215949，肩相对腕位置 .491163→.352774。全片可见性不足，仍为 UNKNOWN。这是同一开发样例的可修正性证据。
R70 的已知 codec residual 操作比直接 RGB 重编码更接近指定的 RGB 重排目标；历史离线映射下 RGB8 误差降低 13.99%/17.43%。该映射来自最终视频，只证明算子保真性。新实验的映射须来自本次当前 x0。

2. 开展条件与样例边界

先由 P1 成片和固定的源动作检查点确认：任务的外观编辑成立、待保留动作仍存在、原时间有残余偏移且可以观察。保留本轮全部 P1 样例及失败记录。用于后续机制诊断的样例标为 development，不把选择后的结果当作无偏发生率。
首轮仍选 index6 一次观察和一次干预；沿既有 first2s（原 8fps 点 0..15）范围。若 P1 只有其他区间可测，需先单独登记新的范围及依据，再生成新对照。此轮检验固定观察时刻的反馈能力，自动决定全部观察时刻和空间范围留待后续验证。
P1 各次推理统一新的完整 prompt、原视频、目标图、参考顺序、shape、模型、kernel、20Euler/sigma、CFG1 和实际 AV 噪声。R65 的 P0 φ、cache、bin 边界仅作历史证据。新输入的条件 tensor、index0..5 及 index6 hook 前 state/x0 应逐位一致。用相同 seed 不能代替这项实际检查。

3. 从当前预测估计时间对应

记去噪步为 i，视频内原始 8fps 时刻索引为 t；两者分开记录。z_i 是当前 CFG 聚合结束、进入自定义 hook 时的视频 clean endpoint，y_i=D(z_i)。从 y_i 的原 49 个时刻提取姿态。
固定沿现有 DP：共同的左右上臂方向、置信阈值 .3、缺失代价 2、映射增量 0/1/2、最多连续重复 2 次、最大偏移 8 个原帧、首尾 (0,0)/(48,48)；等代价优先最接近 identity，再按固定索引顺序。参数沿 PROTOCOL.json，无额外调参。
本协议固定 φ(t) 的含义：为了在参考时刻 t 展示正确动作，读取当前生成预测 y_i 的 φ(t) 时刻。φ(t)>t 对应读取较晚画面，使该动作提前出现。这个方向必须用已知合成移位的 CPU 例子核验。
全 49 点拟合后，只消费预先登记、具有双臂实际观测支持的时间范围。缺失区间的路径是约束补足，不能作为被观察到的对应。所用 RGB 插值的两个邻点均须有支持；.3/.5 两档均需覆盖≥.8、至少 8 点，并检查映射和边界闭合。沿原 0..15 区间时，要求 φ(0)=0、φ(15)=15；不满足则本例 INELIGIBLE。闭合约束会限制可处理样例，单独报告拒绝率。
输出每个原时刻的 φ、support、拟合代价、采样重复次数、边界约束状态。展示完整 49 点路径。原视频 8fps 的事件定位分辨率是 125 ms；插值产生的坐标小数不提高真实动作观测分辨率。

4. 如何区分可重定时成分与动作形状残差

在完全相同的可见点交集上比较 identity 和 φ 两种对应，并分别保留左、右臂结果。用一个共同 φ 对齐两臂，可以检查动作之间的相对关系是否一致；分别给两臂各拟合一条 φ 会掩盖这种问题。
记录四类连续量：原时间误差、重排后的方向误差、未拟合前臂/腕位置误差，以及动作转折顺序/实际时刻。左右臂幅度、视角、关节结构和接触关系另作视觉记录。上臂方向变近可能伴随投影变化，因此配准残差不直接命名为“纯形状误差”。
以下结论范围预先固定：
• 同一 φ 在两臂及未拟合特征上同时改善，动作顺序保留：支持存在可通过共同时间映射修正的成分。
• 一臂改善而另一臂明显变差，或需要倒序、长段重复：当前共同时间映射解释不足。
• 重排后仍有幅度/结构错误：保留为动作形状与观察差异，可能与相位问题共存。
• 可见性不足或事件重复使对应不唯一：UNKNOWN。
原 5% 单侧恶化阈值是预设工程筛查，缺少独立校准；同时给出实际数值。前臂/腕位置虽未参与拟合，仍与拟合特征共享关节估计器，不能视为独立动作真值。后续真正的自动阈值需要源数据合成移位、幅度改变、缺失和错误动作等对照校准，本轮不从同一个成功例子反推阈值。

5. 修正算子及本次必须补的检查

在 float RGB 上按固定线性插值形成 Wφ(y_i)。原 8fps 映射乘 3 后插值至 24fps；可信范围之外取 identity，147 有效帧之后的 padding 取 identity。
  e_id = E(D(z_i))
  e_φ = E(Wφ(D(z_i)))
  Tφ = Lφ(z_i) + [e_φ − Lφ(e_id)]
  Δ = M ⊙ (Tφ − z_i)
这里的 residual correction 继承 LookingGlass/LongE2V。Lφ 沿现有 H3 非均匀 latent 名义中心插值：17⌊j/5⌋ + [0,2.5,6.5,10.5,14.5]_(j mod 5)。这些坐标描述名义分箱，不代表 VAE 感受野或 MM-RoPE。
M 的算法沿原设计：输出范围和读取插值邻点均完整落入可信范围，最后两个可用 bin 的半余弦衰减为 .75/.25。新 P1 的实际 mask 从当前 φ 和 layout 计算并归档；旧 P0 的 bin0..10 数值不能直接照搬。
首先保存三份可看输出：y_i、Wφ(y_i)、D(z_i+Δ)。检查实际 masked proposal 在原时间的动作改善和边界伪影。RGB 目标有效而 latent proposal 无效时，下一项工作集中于算子/支持域。算子检查通过后再开展完整反馈。
identity φ 必须返回 z_i 的精确副本。可以做 CPU 恒等性和独立解码核验，不需要额外完整 DiT 视频。VAE 的时间感受野会使边界外 RGB 受到影响，须观察所有有效帧及 17 帧块交界。

6. 三次完整推理足以回答第一项因果问题

| 运行 | index6 返回的 endpoint | 目的 |
| A | 原 z_i；执行相同观察/计算，记录 proposal | 提供同环境、同生命周期的原始轨迹 |
| B | z_i+Δ | 检验一次普通 endpoint 替换的保留性 |
| C | z_i+λ_signal Δ | 检查 B 的实际写入量是否过小 |

A/B/C 使用同一当前 z_i 和同一 proposal。可以复用 A 的计算，但必须核对本次 index6 的实际 state、endpoint、条件和 raw SHA；不相同即丧失配对资格。缓存成本和首次在线计算成本分别记录。
这三个运行能回答“合法的当前预测修正是否能经实际采样影响最终动作”。它们不能单独证明局部 φ 优于统一移位，也不能证明自动触发策略优于固定时刻。

7. 精确 Euler 写入量与 H3 尺度

实际调用链：BasicGuider → cfg_function → sampler_post_cfg_function → sample_euler.to_d → 被动 callback → Euler 更新。应通过 post-CFG hook 的返回值写入。原 H3X0Readout callback 在 to_d 之后，返回值不参与更新。
  x_(i+1) = x_i + (σ_(i+1)−σ_i)(x_i−z_i)/σ_i
  z'_i = z_i + λΔ
  x'_(i+1)−x_(i+1) = c_i λΔ,  c_i=(σ_i−σ_(i+1))/σ_i
现有 index6 的 float32 sigma 为 .9655172228813171 和 .9570552110671997。c_i=.00876422668967511，所以 B 实际写入约 0.8764% 的 Δ。
令 ε_hat=[x_i−(1−σ_i)z_i]/σ_i，可将原 Euler 结果表示为 σ_(i+1)ε_hat+(1−σ_(i+1))z_i。C 选择 λ_signal=(1−σ_(i+1))/c_i=4.900008917，使下一 state 的当前估计 clean 部分替换为修正结果，保持这一代数分解中的 ε_hat 不变。
这项增益是 Euler 关系的标定。ε_hat 只是当前预测所定义的代数噪声估计，不保证等于真实初始噪声，也不保证调整后的 state 仍严格服从模型训练分布。C 的画质和后续响应必须实测。
H3 视频 process_latent_in/out 的缩放为 1；VAE 内部已经处理 channel mean/std。现有保存的视频 x0 与 hook 的 video endpoint 属于同一归一化空间，encode 结果可直接用于上述公式。音频 sampler slice 带有单独 ×4 缩放；hook 返回原 packed 音频切片。仅本步音频直接更新保持一致，后续联合 AV 推理可产生间接变化。
每条记录 pre-hook x_i/z_i、post-hook endpoint、实际 x_(i+1)，独立核对上述公式。严格 20 次 hook 调用，仅 index6 非零一次；音频、元素总数、dtype、shape、sigma 和注册唯一性都需实际断言。实现时使用预先确定的 float32 容差检查算术残差，同时保留绝对误差、相对误差和 ULP 统计。具体容差应在新 hook 的 CPU 算术回归中冻结，当前提案未部署该 hook。

8. 成果或失败分别意味着什么

• 直接 RGB 重排没有改善：本例对应估计或可测性不足。
• RGB 目标改善，D(z_i+Δ) 没有改善：当前 codec/分箱/边界操作尚未实现期望修正。
• proposal 改善，实测下一 state 不符合 c_iλΔ：接线或实现失败。
• 下一 state 写入正确，index7 预测已无可测改善：该剂量没有形成下一预测可见的动作修正。保留网络响应、噪声层级和观测误差三种解释。
• index7 改善，index12/19 和成片逐渐恢复原偏移：支持后续去噪削弱了早期修正。
• 成片原时间动作改善，编辑身份/幅度/顺序/边界质量仍合格：支持一次当前 x0 反馈在此例有效。
因此保留 index7、12、19 的 hook 前 endpoint 与成片，按同一源动作检查点评估。index19 已接近最终结果时可以核实最终 latent/解码一致性后复用，避免重复 decode。
首轮执行顺序：A 当前 proposal检查 → B → C。若 proposal 本身失败，先归档该失败并调整对应或算子；全量继续推理不会解决它。

9. 成功后才需要的两个有信息量对照

第一项检验 codec residual 的作用：同一 φ、M、sigma 和 λ，比较直接 RGB 重编码 e_φ 与 transport。要同时记录 identity 重编码 e_id−z_i 的影响，否则差异混合了时间修正与原 VAE 往返偏差。可先用同 state decode 解释这个差异；若要声称它对最终推理有独立贡献，再加完整 raw-reencode 和 identity-reencode 对照。原设计 D 只能支持两种执行方案的总体比较。
第二项检验局部时间对应是否必要：在另行冻结的后续实验中比较共同 φ 与当前预测估计的单一全局时移，保持同支持域、边界规则、codec 和写入增益。该对照可分辨局部速度变化和统一延迟；本提案不预设其优胜，也不使用最终视频拟合去选择移位。
若 B/C 均失败，原设计的 index19 末端功能对照可检查输出路径；其 φ 来自更晚预测，不能据此单独归因早期修正被冲掉。优先依据已经记录的 index7/12 轨迹定位问题。

10. 与已核对工作的具体关系

ReTime/SPF 先分析已生成视频的语义进度，再据此重排 temporal RoPE，含频率和去噪时刻强度策略。我们的候选从当前 clean 预测对照参考动作估计时间映射，执行于 endpoint；任务目标是参考时间继承。观测后重定时这一思想已有来源。
https://arxiv.org/html/2604.22554v1 （§3.2、§4.1）

LookingGlass 已将预测 clean latent 解码、变换、重编码，并加入变换后的 codec residual；identity 保持也已写明。该算子作为引用的既有模块。
https://arxiv.org/html/2504.08902v1 （§4.1，式7–8）

LongE2V 已把 RGB 重编码和 residual correction 用于视频时间翻转。把上述技巧用于视频时间轴同样已有直接近邻；其完整生成框架含训练。
https://arxiv.org/html/2607.08770v1 （§3.3，式3–6）

FlowMotion 对源/目标 clean latent 及其时间差分构造引导，再优化目标 latent，辅以速度正则化。当前预测中的运动信息可指导推理已有充分先例。我们的待测操作保持当前生成内容，以共同时间对应重排它，并追踪实际 Euler 写入后的阶段响应。
https://arxiv.org/html/2603.06289v2 （§3.3–3.4）

Motion4Motion 建立跨主体对应和运动轨迹，把目标首帧 K/V 特征按目标轨迹设置 RoPE 后加入 attention。我们当前候选操作整个当前预测的时间轴，尚无跨主体点轨迹或空间可见部位注入；“保持目标外观同时继承运动”的大目标已有直接近邻。
https://arxiv.org/html/2607.11644v1 （§3.2–3.3）

Upscale-A-Video 官方代码已在选定步计算 x0、作光流传播/融合，再调用 step_vt 继续采样。因此“修改 x0 后接着去噪”的入口也属于已有技术路径。
https://github.com/sczhou/Upscale-A-Video/blob/10ca1d751cad25b8ac0b9b0cab415a82d9df1ac6/models_video/pipeline_upscale_a_video.py

潜在可研究差异落在：参考动作与当前预测之间的可观察对应、共同时间修正的适用性判断，以及依据实际下一步动作响应决定继续干预的策略。以上三项仍需算法与实验支持。当前三次因果对照只建立可执行性和保留性；DP、codec residual、Euler 标定和固定 index6 不能分别作为新架构贡献。此次核对覆盖所列方法，未据此声称不存在其他同类工作。
