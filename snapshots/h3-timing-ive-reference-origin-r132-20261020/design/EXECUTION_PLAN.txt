R132: reference-branch origin alignment, existing R17 operator configuration control

Question
Does aligning only the auxiliary video-reference branch improve R122 book-action timing while retaining the blue-book edit? R129 globally changed target video/audio positional relations and failed the blue edit in initial review. R132 keeps the original joint attention and original reference group mass at each same-input attention call. Its late, fixed execution interval matches the existing fixed-guidance control.

Operator
Let q,k,v be the original post-RMSNorm/post-RoPE Q,K and unrotated V. Let R contain every video-reference key, with no temporal bin restriction. Let L_all and L_R be original joint/reference logsumexp. m=exp(L_R-L_all), clamping only tiny positive kernel error in the log ratio.
z_original=softmax(q K_R^T/sqrt(d)) V_R.
Delta=original_output_video_origin-reference_video_origin, read from the actual canonical PackedLayout.
z_Delta=softmax((R_t(-Delta)q) K_R^T/sqrt(d)) V_R.
O_new=O_original+alpha*m*(z_Delta-z_original).
alpha=1. Steps zero-based6..14 (7th–15th sampling calls), all50 DiT blocks. Query scope is the same all32 latent bins used by R122 fixed guidance, covering106 valid/107 generated frames. All reference-video keys compete. Reference/text/audio queries are untouched at this call. Original joint Q/K/V, PackedLayout, rotation table and token ordering remain unchanged. Downstream states can change.

Relation to existing work
This is an existing R17 operator configuration control, not a new algorithm claim. It differs from R129 global media-clock alignment in scope and timing. It differs from current same-bin fixed guidance only in auxiliary conditional reference distribution. Mass preservation is algebraically group-LSE compensated reference logits. The displacement is geometry-derived, not a measured motion error. Approximate bf16 second rotation can differ numerically from recomputing a full rotation table; tests establish float64 geometry equivalence and actual runtime records dtype.
