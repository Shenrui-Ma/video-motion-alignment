R2 (.41) 与 R3 (.9) 实际输入差异核对
2026-10-16；CPU 只读检查。没有修改远端文件、环境、活动配置或 GPU 进程。

结论

跨机差异确实存在于 tensor 内容，不能用 JSON 内的 run_id、路径或元数据不同解释。两机源 MP4 完全相同；全部 141 帧解码后的原生 YUV420P 字节流也相同。最早可复现的不同发生在 PyAV 的 YUV→RGB 转换路径。

.41 实际服务因 PYTHONPATH 优先导入 runtime_deps 的 PyAV 17.0.0；.9 使用 PyAV 16.0.1。同一 .41 机器改用原有基础环境的 PyAV 16.1.0（仅本次 CPU 子进程，无环境修改）后，全部 141 帧的 float-RGB SHA 精确变为 .9 的实际输入 SHA。这将已观测到的最早输入差异定位到颜色转换的软件路径，而非源片、帧序、H264 解码内容或 GPU 计算。

这不证明 DC 算子跨机效果不同全部由颜色转换造成。身份参考图 prepared RGB 在两机一致，但其 VAE latent 已不同；后续模型运行还存在 Torch/CUDA/设备数值环境差异。现有跨机结果只能描述为不同实际预处理与计算环境下的复现，不是“仅 GPU 不同”的严格因果对照。

三、实际 conditioning 差异与配对

RESULTS.json 比较的是 shape/dtype/raw SHA，移除 tensor_file 后进行字段对比，不用 JSON 文件 SHA 代替 tensor 内容。

因此每机内部 DC/full/static 等控制的实际输入与噪声配对成立。跨机可以比较结果是否稳健，但应明确预处理及计算环境共同改变。若要隔离设备/内核数值影响，需要之后冻结并交换同一实际 prepared RGB 或完整 conditioning tensors，而不是只保证同 MP4/seed。此建议未实施，不修改当前实验。
