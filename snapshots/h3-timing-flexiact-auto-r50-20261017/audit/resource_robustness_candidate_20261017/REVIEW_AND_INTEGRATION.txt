精确变更（各版本均仅 4 个源文件）
1. extensions/H3AutomaticWindowRouter/transport.py
   - ResourceUnavailable 与 AdmissionIntegrityError 分开；只有资源状态可重试。
   - GPU memory/compute 原始查询与 PID ownership 快照进入 JSONL 审计。
   - 对其他用户只读取 UID；本用户及预期父进程核对 PID/start ticks/command SHA。
   - admission 仍要求主模型独占指定 main GPU，decoder GPU 空闲，所有本 UID
     已用卡仅有 main。这在加入 decoder 后保持最多两张自有 GPU。
   - wait_decoder_admission 共享本 observation 的 600 秒单调时钟截止点。
   - run_child 增加可选执行阶段计时：收到绑定本次 child identity 的 start
     marker 后，独立限制执行时间为 180 秒。其他调用沿用原有总预算逻辑。
   - response 验证改为本次 decoder generation 与 NVML 尾已释放的证明。
2. scripts/run_observer.py
   - 等待资源、保存现场；向 child 传同一截止点与独占 start marker 路径。
   - 父监督总预算=剩余资源等待+180 秒；CPU pose 的 840 秒上限沿用。
   - 解码后检查自身释放，随后进入 CPU pose。其他人在 GPU2 开始工作会
     出现在记录中；下一次 decoder 准入重新检查卡是否空闲。
3. scripts/decode_live_child.py
   - 两次准入检查均支持有界等待；第二次之后再次验证 request/endpoint。
   - CUDA 初始化前写入本次 child 的 execution-start marker。
   - VAE load/decode、归一化、FP16、RGB 写出及异常处理计算体保持逐字一致。
4. scripts/gpu_release_gate.py
   - 新增 wait_own_child_released：只等待自身 PID generation/NVML 尾，最多10秒。
   - 同 PID 新 start ticks 记为复用；同 generation 即使命令变化仍硬失败。
   - 原 wait_after_child 保留逐字不变，供 standalone 资源证书继续检查整卡空闲。

限制与风险
- NVML 查询与 CUDA 初始化之间仍存在竞争时间窗；共享集群没有原子 GPU
  预留。此补丁通过等待和再次查询处理常见竞争，不能建立独占调度保证。
- 单次 nvidia-smi 查询最多10秒；两次查询可能使终止响应超出资源截止点
  少量时间。超过截止点取得的“可用”结果会拒绝 CUDA 准入。
- 600秒资源等待与180秒执行使用同机 monotonic 时钟；不能跨主机复用该值。
- decoder 只在成功回收后进入 release 验证。未知 compute ownership 会等待；
  不会将其当作其他用户而放行。退出后自身 NVML 尾超过10秒仍会失败。
- 资源等待期间主模型继续驻留 GPU；结束观察超时后由原生命周期机制回收。
- 仍需真实环境检查：查询格式、GPU驱动NVML延迟、目录权限、开始marker读写，
  以及实际解码耗时。全部测试使用 stdlib mocks，未做 CUDA/inference 测试。
