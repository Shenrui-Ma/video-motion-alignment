# 官方 MF 固定轨迹变换诊断

此目录仅做 CPU 指标敏感性诊断。输入是五条已缓存的源视频 CoTracker 轨迹；所有变换为合成轨迹诊断，不对应生成视频，也不衡量 H3 方法效果。

在首次计算分数前冻结 `PROTOCOL.json`，绑定官方 MF 源码、缓存文件与来源报告 SHA。固定五个 ID；不按轨迹运动程度、输出分数或可见性挑选点。

每条源轨迹有效长 N、24 FPS。固定六项：

1. 全长原轨迹自比，物理域 0..N−1。
2. 共同域自比，物理域 t=8..N−1。
3. 延后 2 帧，参考 s[t]、目标 g[t]=s[t−2]。
4. 延后 4 帧，参考 s[t]、目标 g[t]=s[t−4]。
5. 延后 8 帧，参考 s[t]、目标 g[t]=s[t−8]。
6. 共同域中央 8 帧目标 visibility 置零，其余坐标/可见性完全不变，真实 lag=0。

2–6 的物理评价域一致、长度 N−8、间隔 1/24 秒。延后变换同时平移坐标与该时刻的可见性。缺口起点为共同域数组下标 floor((N−8−8)/2)，区间采用左闭右开。既不端点重复，也不循环或插入坐标。每项保存物理时间、参考和目标原始帧索引、目标原内容时间以及输入 visibility。

原官方函数内部会重新插值可见点；该行为原样执行并在解释中区分输入真实时间与评分内部时间。使用 SHA 绑定的官方文件，AST 仅提取 interpolate_track、compute_frame_by_frame_similarity、synchronize_videos、_compute_similarity_from_tracks 四个原样方法，避开 tracker 依赖导入；不改方法 AST、不重写公式。输入保持 CPU Torch tensors。禁止构建模型、tracker forward、CUDA 或 MPS 运算。

先运行针对变换时间映射、缺口、方法 AST、人工线性轨迹已知值、缓存 SHA 的 CPU 测试，再执行全部 30 项。总评分有 180 秒进程内时限；若遇到资料不完整/非有限值，保存失败并保留固定分母。只描述此五条、此变换和原评分函数的反应；不提出新指标，也不据此推导生成视频的动作正确性。
