5. 两个最小反向干预的工程定义（仅可行性，未实现）
采用父任务预定的两臂：同 source05/Sam/seed1311、同 W50…65→bins[14,20)、同 step indices6…14、同全部50层；只选 R 的事件 query 集合[21112,26770)，全部空间，无 ROI、没有新增扫描或 forward/reverse 组合。
从实际 validated layout 推导索引，不硬编码87592。R 与人物图都标为 ref_img，必须使用 conditioning.refs 唯一 video 的完整重建元数据，不能按 kind=ref_img 随意选第一个。
令 J 为全部 T video keys，C 为其余全部 keys；Q_R 为上述参考事件行。对每个 query/head：
 O=A_all(Q_R,K,V)，O_J=Attn(Q_R,K_J,V_J)，O_C=Attn(Q_R,K_C,V_C)，
 m_J=exp(LSE_J−logaddexp(LSE_J,LSE_C))。
A. BLOCK：将选中 R query 输出设为 O_C。它等价于在这组 query 对全部 T video logits 加 −∞，正确重归一化保留组。不能只减 m_J O_J 而不除剩余质量，也不能把 V_T 置零充当屏蔽。直接算 O_C 可避免1−m_J接近0的减法不稳定。
B. SAMEBIN：对 R 的 bin b，用原生带 RoPE 的同一 Q_R 读取 T 的同 bin 全空间943个 K/V，记 O_J,b。设 O'=O+alpha*m_J*(O_J,b−O_J)，alpha=1。保留原 Tvideo 组总 mass，只重分组内时间支持；C 的每个原概率贡献保持。该式与已有 forward Full 对称，不能据“换了方向”单独声称新算法。
两臂共同只覆盖参考事件 query；原生成 query、text、人物图、audio 及事件窗外参考 query 在该 attention 调用的输出不覆写。BLOCK 保留 target audio，生成仍可经 audio/text/其它 reference 行进入 R；故它不是完整生成→参考隔离，也不等同文献里可能阻断全部 generated tokens 的 mask。

最小代码面：新独立节点复制已验证 RouterState/layout/lifecycle，以新执行器通过 DiT block patch 的 attention override 接口介入（model.py:755–762；R2 EventBlockPatch/LocalAttentionOverride）。在原 attention_pytorch 全输出上只替换 R 行，额外对选中 R query 计算组内 Flash+LSE。无须更改 checkpoint、全局 Comfy attention、sampler、RoPE、VAE/refiner。SAMEBIN 可从 LSE_J/LSE_C 得 m_J，无须持有 N×N attention matrix。直接保留原 native 全输出，能避免为了取 LSE 而切换整幅输出后端造成未选行数值差异。成本会增加局部 attention 调用，实际仍20 DiT NFE/20 Euler；须记录时间与显存，不把额外 attention 次数说成额外模型采样。

6. 可验证不变量与最省新增 GPU 的证据
CPU 先验测试：小 QKV 与显式 dense softmax mask 对照；BLOCK 正确归一化；SAMEBIN 每个 query/head 的组总 mass 保持；边界/身份图排除；alpha0 直接原生；输入 Q/K/V、RNG 不变；坏 mask/layout/重复 wrapper 拒绝。有限精度 dense/kernel 容差须在实际结果前冻结，不能因失败临时放宽。
首次改动在 index6/block0，其输入沿 native prefix：保留原 native attention output，记录选中 R 行改动的 finite/差值，逐位核所有非选中行，重点 Tvideo+targetaudio；同时记录 W_O/residual/FFN 后 T hidden 与同输入原生 block 对照（若增加独立重算须计成本；更省的方案是输入与逐行依赖审计加被动 hash，而不伪称已有原生中间 hidden）。下一层应记录 R 的输入 hidden/K/V 已受影响的可检验签名及 T 输出差值；若没有实际同输入 native 中间量，差异只能通过额外局部重算或专用 paired replay证明，单臂相邻层不同 hash 不能当因果证明。
这项区分应写进验收：当前 attention 中 T 行 bitwise未改可由同一次 full native 输出直接验证；“下一层传播”需要 paired native 对照，不可从一次运行自己前后不同直接推出。推荐在第一次 active forward 保存必要的 block0出口和block1 T行小型固定投影/签名并在配对 native replay时取完全相同位置；完整 reference hidden 若保存开销大，可先预登记固定通道投影，但它只能检测不能排除遗漏变化。
作为结构负例，若只在最后 block49 改参考行，后面没有新的跨 token attention，数学上最终 Tvideo/audio 应不变。冻结 INT8 row-chunk实现 scripts/int8_row_chunking.py:23–30 记载激活逐行量化、SwiGLU/ConvRot逐行；但正式 mixedprecision/kernel 路径仍须实际核，不把理论直接称GPU逐位通过。仅当保持同 native全输出且其它算子行独立、无隐藏全局量化尺度/缓存变化时，最终逐位不变才成立。这个可以先在真实CPU小模型验证，暂不追加第三条完整GPU臂。
最省正式新增视频是父任务的两臂各20步，沿既有 R3 Native 与 forward Full 作为比较；总新增40 NFE，不重跑已验证全部历史。必须绑定原R3 actual conditioning、noise、完整sigma/backend/seed、输入素材SHA；两新臂的 native prefix005 video/audio 与旧R3实际端点逐位相等，且20callback/1000blocks、每层9次反向操作均通过。旧prefix005并不能自动证明所有processedcondition树相同，仍按现有完整condition/noise审计重新绑定。
若在进入两条完整视频前需要真正同输入下一层传播证据，最小独立诊断是用已存 R10 index6 raw x（仍与R3共同native前缀绑定）、sigma/conditions 做一次 native replay，再各做反向臂相同x的forward，总3NFE。必须匹配旧端点和actual input SHA；不能把端点改善当完整视频成功。可选择这项或在正式两臂内增加上述中间量对照，不要默认同时开展。当前文件不批准任何额外GPU。
结果解释：BLOCK改善只支持切断该边有作用，仍混合了总mass变化与归一化变化；SAMEBIN改善可说明在固定总mass下时序分配有作用；若两者均无改善不能推导所有反向方案无效。质量/时序须连同手腕、方向、躯干/腿部、身份/重影评价；只能使用实际生成的两臂结果。
