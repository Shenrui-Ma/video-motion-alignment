# Fitness 的官方 MF 逐点分解

实际 Native MF 为 0.6865184307，固定时序引导为 0.7362017632，增加 0.0496833324。由原始 similarity.pt 提取 3025 个逐点分数，按作者公式 `s_i = max_j(M_ij - identity_ij)` 求均值，与原 SCORE.json 以及冻结的 get_score 函数逐位一致。

Native 与固定引导的 3025 个首帧查询坐标完全相同，最大坐标距离为 0 像素。2613 点分数增加，412 点降低；Δ 中位数 0.050008，范围 −0.221735 到 +0.317615。逐点差值均值与两个总分相减存在约 3×10⁻⁸ 的 float32 归约顺序差异。

图中正向变化分布在背景两侧、头部和身体多个位置，手臂附近同时有正负变化。该分布与“前 2 秒双臂延后仍为 375 ms”的独立姿态结果同时成立。图示支持 MF 增益分布较广，当前证据无法把总分增益归因为上肢动作时间得到修复。

这些点的颜色表示完整 49 帧轨迹的方向匹配分数，绘制在各自首帧位置上。作者公式允许每条编辑轨迹在全部源轨迹里取最大相似度；它不要求保持同一语义部位的对应。首帧位于背景的点后续可能穿过遮挡或人体边缘，因此这里没有用首帧方框估计前景比例，也没有把可见背景点称为全程静态轨迹。没有可靠的前景 mask。

## 文件

- `fitness_mf_point_maps.png` / `.pdf`：上排实际首帧；中排原官方逐点分数；下排固定引导减去 Native 的差值，分别叠在两张首帧上。
- `fitness_contributions.json`：全部坐标、逐点分数、最佳参考点索引、差值和输入 SHA。
- `fitness_point_scores.csv`：3025 行数值。
- `ACTUAL_FILES.json`：远端和本机归档核验的 SHA。
- `PROTOCOL.json` / `PREREGISTERED_FILES.json`：运算前冻结的设计与脚本 SHA。

复用既有 similarity.pt、tracks.pt 和原作者函数；CUDA 未初始化，tracker 调用为 0。未改推理、轨迹、官方评分公式或现有成片。
