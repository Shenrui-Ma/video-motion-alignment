Math and exact historical geometry
----------------------------------
The original attention.forward still computes QKV, Q/K RMSNorm and RoPE; the
intervention receives those tensors, recomputes only the selected target query
rows, and merges them before the original output projection. No dense mask.
Three identical copies of a selected key/value in the softmax sum are equivalent
in real arithmetic to adding ln(3)=1.0986122886681098 to that key's logit.
The odds against unselected keys are multiplied by 3. If selected-set probability
mass was p, the new mass is 3p/(1+2p), not generally 3p.

Historical audited QKV: [1,56,87583,128], bfloat16.
Source event requested [39,44] inclusive; H3 temporal bins [12,14) cover [39,46].
This is a positional-bin mapping, not a strict VAE receptive-field guarantee.
Each latent frame has 943 spatial rows; selected K and Q each contain 1886 rows.
Historical absolute K=[19217,21103), Q=[59293,61179).
Factor 2 weighted K/V length=89469; factor 3=91355.
The isolated metadata fixture uses different text length and absolute offsets;
production layout must be reconstructed and verified at runtime, never hardcoded.

Memory/runtime risk
-------------------
The two K/V concatenation allocations total:
  factor 2: 2,565,255,168 bytes = 2446.41796875 MiB
  factor 3: 2,619,330,560 bytes = 2497.98828125 MiB
  increment: 54,075,392 bytes = 51.5703125 MiB
Factor 3's duplicated rows alone are 103.140625 MiB across K and V; this is
already included in the concatenation total, not additional to that total.
The selected-query output is 25.78515625 MiB. Original QKV/full output remain
live; actual peak may be much higher and depends on Core/runtime/kernels.

The local recomputation score count is M*(N+(f-1)*M); it is ~2.2461% of the
full N*N attention score count at factor 3, versus ~2.1998% at factor 2.
This is arithmetic accounting, not a runtime prediction: torch.cat copies
the entire K/V sequence and backend dispatch/workspace/allocator effects matter.
The baseline full attention still executes, so factor3 is not 1.5x or 3x the
whole model work. Reuse the existing native SDPA experiment backend; do not
silently add Sage or another attention.forward override.

Archived admission_benchmark.json recorded a factor2 live-sampling GPU snapshot
of 62,554 MiB on host 172.18.33.9. It was not an instrumented peak and provides
no capacity proof for a different server's 48 GiB GPU. Factor3's modest extra
slice storage is not the dominant cross-runtime capacity issue. Preserve all
141 frames and the scientific recipe; investigate runtime memory independently
and record any changed configuration. The archived INT8 row-overflow guard
also needs compatibility review in the selected runtime, not blind omission.
