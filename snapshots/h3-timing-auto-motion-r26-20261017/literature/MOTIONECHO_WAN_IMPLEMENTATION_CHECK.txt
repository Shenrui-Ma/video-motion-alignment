B. Paper's Wan configuration (reported, not executable verification)

The v2 paper uses original Wan2.1-1.3B as teacher and Video-BLADE LoRA on the same base as student. Custom UniPC maintains teacher/student trajectories, typically 200/8 steps. Null-text reference encoding supplies block15 K/V. Objectives include MOFT, DMT and DiTFlow; latent Adam uses five inner iterations. Teacher CFG is5; student is single-branch. Output is480×832,25frames,8fps. Adaptive settings include loss averaging W2, at most3 teacher events, lambda.5 and thresholds20/18. MotionEcho is training-free at application time; its distilled student was pretrained. Wan2.2 extensions use corresponding5B teachers/students and49frames. All experiments report A100-40G. Table12 lists VB MotionEcho peaks12.66/12.72/17.82GB for MOFT/DMT/DiTFlow. These are reported configurations, not our resource measurements. The published pseudocode is explicitly TurboV2, so it cannot substitute for the missing Wan implementation.

D. Comparison selection with the existing Wan feasibility note

FlowMotion remains the strongest immediately implementable reference-motion candidate among these three: actual run.py accepts video_path and target text, defaults to Wan2.1-T2V-1.3B-Diffusers, resizes by arguments (480×720 default), uses all loaded frames and exports the source FPS. README examples cover49/81frames and claim a single RTX3090 setup. Its official implementation can be pinned and tested without inventing a teacher or a portrait interface.
https://github.com/HKUST-LongGroup/FlowMotion/blob/main/run.py

TempoControl has real Wan code, but the current README specifies about110GB on one GPU and offers Ulysses multi-GPU execution. The existing feasibility note correctly separates its concept/timing-signal task from reference-motion preservation. It is a candidate for explicit timing control after task/input adaptation and resource validation, not an interchangeable portrait-editing baseline.
https://github.com/Shira-Schiber/TempoControl/blob/main/README.md

MotionEcho currently cannot fill the second runnable-author-method slot. Reimplementing its equations on Video-BLADE would be our reimplementation with unverified scheduler, guidance, preprocessing and adapter choices; it must not be labelled authors' code reproduction. The available BLADE text-only sample is likewise not MotionEcho. Keep the second slot open pending a task-compatible official implementation or a future author release; do not rush a nominal two-method table.

E. Minimal future fairness contract (our proposed evaluation conditions)

First separate two tracks: undistilled Wan2.1-1.3B methods, versus the same fixed Video-BLADE student with/without MotionEcho. Comparing those tracks changes the generator as well as controller. A meaningful common-Wan experiment needs a fixed backbone/checkpoint and exact permitted inputs: source video plus target text, with portrait identity only when every method has an equivalent supported interface. H3's joint reference-token actuator does not carry over automatically to a Wan T2V pipeline.

Preserve physical time before changing frame counts. The paper's25frames/8fps and BLADE code's81frames/16fps differ from each other and from our141frames/24fps. Predeclare shared frame timestamps, clip duration, resize/crop and VAE4n+1 constraint. Re-measure local motion delay in seconds and frames on the common sequence; simply changing playback FPS can manufacture apparent timing gains. Report rejection/UNKNOWN and all preselected sources, not only visually successful outputs.

For a later MotionEcho release, require executable Wan entrypoint, exact teacher/student/LoRA revisions, motion-objective choice, reference sampling, scheduler/grid and adaptive settings, source inversion/precompute accounting, and a reference output or smoke fixture. Count teacher/student forward and backward work plus inner optimization and preprocessing; an eight-step label alone is not total NFE. Establish each author's default first, then label every common-task or geometry adaptation separately. Peak-memory and speed claims above require a new measured admission at our selected geometry.
