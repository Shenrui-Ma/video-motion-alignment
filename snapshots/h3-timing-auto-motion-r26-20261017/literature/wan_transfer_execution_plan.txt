1. 当前可执行结论

可以在同一 Wan2.1-T2V-1.3B 模型家族上运行两套公开代码，完成“源视频＋文本的外观/主体编辑并保留运动”的交集任务。它们都不原生接受 H3 当前实验使用的身份参考图。不能把带 Sam 肖像的 H3 Ref2VA 和不带肖像的 Wan 文本编辑称为相同输入条件下的方法胜负。首个共同任务宜固定成衣服颜色/外观文字编辑；源描述、目标描述及目标词必须由源内容预先冻结。

H3 Full 不是在 Wan 中改几行现成 reference logits 就能原样工作。Wan T2V 的 self-attention 只有当前视频 Q/K/V，文字走独立 cross-attention，没有 H3 joint stream 的 reference-video group。必须先定义 source reference bank / 双分支，再检验该新增分支的原生影响，才谈“保组质量的同时间读取”。控制器可以复用物理时间误差的定义，但 Wan 编码器时钟、条件语义与执行器都要重新验收。

已下载的只是固定版本小源码、HF 文件清单和配置；论文与代码已读，命令仅模板。没有声称官方仓库已经在本机实跑成功。

3. 两套原生执行路径（代码事实）

FlowMotion run.py：
- 输入 source MP4 + target_prompt；source prompt 和 negative prompt 都是空字符串。全部源帧经 imageio 读取，VideoProcessor 按指定宽高预处理，输出沿用源 FPS。
- 模型/文本/VAE按 FP16 加载；VAE.encode()[0].sample() 取 posterior 样本，继而按 mean/std 标准化。目标从随机噪声起步。
- 每个指导步独立 forward-noise 源 latent，求源预测 clean endpoint；目标 latent 进行 Adam 内循环，对 clean endpoint 和绝对跨帧差值作匹配，再做手写 Euler 更新。无 inversion，无 LoRA，无深网络反传。
- 默认 50 步，前 10 步各 3 次优化，source CFG 1.5，target CFG 6，lr .003，alpha20/beta5，velocity perpendicular scale .1。
- calc_velocity 有 @torch.no_grad()；梯度经过 x0 = z - t*stopgrad(v)，不能删除 decorator 后仍称官方复现。
- __init__ 创建 self.scheduler(flow_shift=CLI)，process 却调用 self.pipe.scheduler。当前 --flow_shift 无效；HF 原配置 flow_shift=3。默认恰好一致，更改 CLI 不会改变实际 sigma。应归档实际 timesteps/sigmas；接通参数属于带版本标记的修订。
- do_classifier_free_guidance 由 pipe._guidance_scale=target CFG 控制，source 两个空条件仍做两次 forward。默认 latent_prediction 的实际 DiT 调用预计 50*2+10*2+10*3*2=180；clean_latent 为160。必须以实际 instrumentation 为准，不能仅报“50步”。

FlowDirector V1 edit.py -> WanT2V.edit：
- 输入 source MP4、source_prompt、target prompt、source_words、target_words；无身份参考图。words 通过 tokenizer 子序列定位，应验证两者都确实匹配，缺失会影响编辑 mask。
- OpenCV 读全部帧，BGR->RGB，INTER_AREA 直接 resize，[-1,1]；VAE.video_encode 返回均值 latent，VAE 默认 FP32。T5/DiT计算配置 BF16；并非 FlowMotion 的 FP16 posterior-sample 路径。
- z_edit 初值为源 clean latent。对每个 noising draw 和 temporal window 构造 z_src=(1-t)x_src+t*noise，z_tar=z_edit+z_src-x_src，调用源/目标各 conditional/unconditional，得到速度差；文字 cross-attention mask 调制更新。无 inversion。
- 官方 shell 默认 50 个调度时刻、n_max40/n_min0、n_avg4/worse_avg2、source CFG3.5、target CFG10.5、shift12、omega2.75、window_size11、decay .25。前10个调度时刻跳过，随后40个编辑更新。并非50次同成本生成。
- Temporal MultiDiffusion 默认 latent window11 / stride8；CLI window_size 是空间 mask pooling 参数，不是这个 temporal window。81 RGB ->21 latent：实际窗口起点[0,8,10]，每步 3 windows。默认 81帧约40*4*3*4=1920 DiT forwards；41帧单窗约640；49帧两窗约1280。不含文本/VAE。以实际计数复核。
- frame_num 只用于 target_shape/seq_len 计算，loader 不裁剪源帧；必须外部准备精确帧数。输出固定 cfg.sample_fps=16，不读取输入 FPS。输入 24fps 直接送入会改变输出的物理动作时长，这不能记成生成动作延迟。
- 官方 README 脚本名下划线写法不对应实际文件；实际是 script-edit-single-gpu.sh。下方模板直接调用 edit.py。

4. DAG 的精确行为与公平边界

在 text2video.py 887–903，令 M 个速度差为 v_i、均值 Vbar。代码枚举所有大小 k 的子集 S，并平均 Vbar - mean_{i in S}(v_i)。每个 i 在同样多的子集出现，故：
  mean_S(mean_{i in S} v_i) = Vbar；mean_S(Vbar - mean_S(v)) = 0。
于是精确算术下 V_final=Vbar+(omega-1)*0，omega 不产生所声称差分增强；浮点可能留微小残差。接着仍乘 active spatial attention mask，其他方法部分没有被这个结论否定。848–851 计算的 conflict_mask 没进入后面的 active 更新；实际用 source/target attention union + soften。

必须分开三种标签：
A. Official V1@commit：原样执行、准确记录 DAG 等价取消及结果。
B. V1 的后续修复：只有另行规定子集选择/排序/参照等，才可能不抵消；这会改变算法，不能用“简单bugfix”假装论文唯一意图，不能声称官方 V2。
C. 我们移植 Wan 的新执行器：独立命名、独立 baseline。
单凭官方 V1 某一退化实现上胜出不能支撑对论文完整算法的优势。后续论文比较需报告 A 的限制；若无可核官方修正版，保留 FlowMotion 为核心可解释对照，不自行降低其参数来获得胜出。

8. H3 Full 迁移 Wan 的最小插入点与必要对照

现有H3：O_new=O+alpha*m_ref*(O_same_ref-O_all_ref)，其中m_ref来自原joint attention对reference视频组的真实概率质量；其他组输出不改。
Wan结构：30blocks，12heads×128，hidden1536，latent channels16，patch[1,2,2]，参考不存在。
原Wan文件 wan/modules/model.py：WanSelfAttention.forward的qkv_fn约138行，qkv约143，RoPE+flash145，flatten154，self.o155。最小hook在视频self-attention post-RoPE / pre-output-projection。文字WanT2VCrossAttention不动。

建议最小可解释适配：
  S_n=(1-sigma_n)*E(source)+sigma_n*epsilon_n；用源条件c_s独立跑同一Wan，各block缓存post-RoPE K_s和V_s。
  target各block原Q_t，组成K=[K_t,K_s], V=[V_t,V_s]，得到bank baseline O_B及真实m_s。
  O_BFull=O_B+alpha*m_s*(O_same(K_s,V_s)-O_all(K_s,V_s))。
  same对应的是该Wan编码格中的物理时间索引，源/目标等fps且等帧数；首帧与后续4帧chunk分别处理。不能沿用H3 17RGB→5latent、50blocks、56heads、bin14..19。
