Prospective follow-up rules, written before R26 generated results and R27 causal runs
2026-10-17

Record every R26 Native source and every reliable/aligned/UNKNOWN window. The
three source clips were selected from source-only motion and visibility; retain
that denominator. Use both confidence settings and fixed equal-time displays.
Screening identifies development failures; it does not estimate a dataset-wide
error frequency and must not become an oracle input to the automatic controller.

Once R27 old-bad and old-normal trajectories are complete, first inspect actual
observed starts/stops, branch/state invariants, timing and visual preservation.
A normal run with no interventions should exactly reproduce its Native result;
any observed difference requires a wiring explanation before a scientific claim.
A timing reduction alongside ghosting or identity damage is a tradeoff result.

For R26 transfer, process eligible failures in frozen source order40372,51304,
51317; the last source supports arms only. A failure candidate needs consistent
visible delay evidence and evaluable common support. Review the candidate's full
local motion segment, retaining the same source/output physical timestamps. Keep
unreliable and normal cases in the ledger. The automatic controller receives the
whole source and edit request, with no screened event window supplied. At least
one already-normal new-source result remains a preservation control.

Freeze a controller version before each prospective generation. The present
0.5 gain threshold and two-step persistence are development hyperparameters.
If results cause a change, create a new version and preserve the old result; do
not relabel the changed version as an untouched held-out test. A second seed and
an additional source are needed before a generalization claim; a pilot can still
fail before that expansion.

After a useful automatic trajectory exists, replay its exact physical-bin masks
with a frozen schedule as a paired ablation. Original fixed Full and automatic
Full change both physical support and denoising schedule, so their direct
comparison alone cannot attribute an effect to dynamic timing. Record NFE and
observer/route/decoder/wall time, without efficiency-driven tuning at this stage.

R25 reverse-edge tests provide a separate actuator diagnostic. Successful BLOCK
alone supports an asymmetry hypothesis already present in prior work. Successful
SAME alone needs a matched wrong-time or sparsity control to support a specifically
temporal feedback explanation. Neither outcome licenses a first-method claim.

Wan comparison begins after a useful H3 rule is frozen. Publish the backbone,
input availability, adapter and inference budget of each method. A controller
ported onto a different actuator establishes controller transfer, not portability
of the H3 attention modification. Compare to actual released implementations;
missing code or inaccessible full methods remain explicit limitations.
