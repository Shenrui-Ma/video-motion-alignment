root GPU 调度接口（watcher 不调用）
  先设置 R 为上面的 .41 consumer 目录，P 为上面的 Python，G 为 root 现场批准的 GPU UUID。
  仅打印命令：
    "$P" "$R/scripts/tracking_plan.py" --key chest --method reference --gpu-uuid "$G"
    "$P" "$R/scripts/tracking_plan.py" --key chest__game_man_5 --method native --gpu-uuid "$G"
    "$P" "$R/scripts/tracking_plan.py" --key chest__game_man_5 --method forced --gpu-uuid "$G"
  目标命令须等 prepared/<pair>/READY.json。
  执行打印的 argv 后，进程在 CUDA 前写 controls/<method>_<key>/ready.json。
  ready 顶层 pid，identity={uid,start_ticks,cmdline_sha256}；原始 cmdline hash。
  root 核验真实 PID/UID/start/cmd、当前显存、input manifest SHA、consumer freeze SHA，
  并把准确身份登记到需要允许此 peer 的推理服务，再逐字复制 ready.json 为 go.json。
  600 秒尚无准确 go 会退出。输入/冻结文件改变会拒绝执行。
  wrapper 允许共享上下文，实际 free >=40 GiB、温度 <85°C、本用户占用并集 <=2 卡。
  保持原 run_tracks.py 数值代码，只有 check_gpu 被独立 wrapper 替换为上述资源规则。
  REPORT.json passed 与真实 tracks SHA/shape 绑定；R74_BINDING.json 留执行来源。
  root 核真实 PID 和 CUDA allocation 退出，然后撤 peer，才进行下一项。
  需要重试时保留旧 attempt，交由 root 指定新 control/output；不覆盖失败记录。
